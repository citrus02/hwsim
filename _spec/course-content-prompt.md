## 起点假设

**玩家在进入第一课时，对该科目一无所知。**

这不是夸张。一年级第一课的受众是：从未接触过这门学科的十一岁巫师学生。写作时必须严格遵守：

- **禁止使用任何未经本课介绍的术语**——哪怕"显而易见"。第一课第一个 keyPoint 出现的术语，必须在该 keyPoint 里定义。
- **禁止假设学生已经知道任何工具或模型**——数轴、坐标系、元素周期表、食物链，都需要先介绍再使用。
- **引入顺序必须自洽**：后出现的概念可以依赖前面已讲的概念，但不能反过来。
- **年级越低，零起点假设越严格**：KS3 第 1 课按零基础写；高年级课程可以引用同科目前置课程已建立的概念，但仍不能跨科目假设。

## 世界观约束

- 游戏时间：**1991 年**，玩家是霍格沃茨一年级新生
- 视角：**研究麻瓜学术的巫师**——认为麻瓜知识有独立价值，态度是真正的学术好奇，不是猎奇或俯视
- 知识内容必须**准确**，学生读完真的能学到东西
- 年级阶段对应英国课程标准：KS3（1–3年级）/ GCSE（4–5年级）/ A-Level（6–7年级）

## 举例原则

**可以用：**

- 魔法世界通用设定（魔药、魁地奇、对角巷、霍格沃茨建筑、咒语机制、魔法生物）
- 模糊化主体："某位变形术学生"、"一次草药课实验"、"巫师社会中普遍的现象"
- 麻瓜知识与魔法的真实交叉点（化学↔魔药、物理↔飞行、生物↔神奇动物、拉丁语↔咒语词源）

**不能用：**

- 原著具体情节或点名引用主要角色的经历
- 上帝视角（破坏代入感）
- 1991 年 09 月 02 日后才发生的事件

## 输出格式

### 课程正文（lesson 文件内容）

```
【第 X 课：课程标题】

导入（1–2 句）
用魔法世界现象引出本节麻瓜概念，符合该教授的开场风格。

正文（2–4 段）
每段一个知识点，知识准确，可穿插 1 个巫师视角例子。
语气和措辞贴合教授人设。

本课要点
· 要点一
· 要点二
· 要点三（至多三条）

[联动提示：与 XX 魔法课相关——一句话，有自然联动时才写]
```

### 题库（questionBank 文件内容）

每课配 3–5 道题，格式：

```js
{
  lesson: X,
  questions: [
    {
      type: 'choice',          // 目前只用 choice
      difficulty: 1|2|3,       // 1=基础 2=理解 3=应用
      text: '题目文字',
      options: ['A. ...', 'B. ...', 'C. ...', 'D. ...'],
      answer: 'A',             // 正确选项字母
      knowledgePoint: '对应知识点名称',
      analysis: '解析，说明为什么这个答案是对的'
    }
  ]
}
```

题目中的情境可以用魔法世界背景包装，但考查的是真实学科知识。
难度分布建议：基础题 2 道，理解题 2 道，应用题 1 道。

## keyPoint context 写作原则

每个 `keyPoint` 由两部分组成：`point`（知识点标题）和 `context`（课堂场景段落）。

### 定义必须明确写出

`context` 的核心职责是**让学生在做题前已经学过该题考查的定义**。

**不够的写法（只有场景，没有定义）：**

> 芬威克在黑板上画了一条数轴，指着中间的点说这个位置很特殊，让大家思考它和左右两侧的区别。

**正确的写法（场景中嵌入完整定义）：**

> 芬威克在黑板右侧写了两个字：正整数。「大于零的整数——」他在数轴右半段点了三下，「1、2、3，向右延伸，没有尽头。」……「零是整数，但它既不是正整数，也不是负整数。」

规则：**第一次引入某个术语的 keyPoint，必须在 context 里明确给出定义**（"X 是……的……"或"X——条件"）。定义可以包裹在教授的对白或板书动作里，但不能只靠暗示。

### 定义与叙事融合，不割裂

- 定义句紧跟术语首次出现，不推迟到段末
- 教授对白 `「」` 用来承载关键定义或强调，叙事文字描述动作/氛围
- 每个 keyPoint context 约 150–250 字；一段到底，不分段

***

## 小黑板（blackboard）规范

每个 `keyPoint` 可以附带一个可选的 `blackboard` 字段，在知识点标题与 context 文字之间渲染一块深绿色黑板区域。

### keyPoint 完整字段结构

```js
{
  point: "知识点标题",
  blackboard: { ... },      // 可选，答题后显示的黑板（含答案、箭头、结果）
  blackboardQ: { ... },     // 可选，答题前显示的黑板（不含答案——见下文）
  question: { ... },        // 可选，课中提问；calculator 可配合 question 做按键后提问
  interactionContext: "...", // 可选，无 question 的互动说明；如计算器按键演示前的引导语
  context: "...",           // 答题后显示的解释（兜底，无 question 时也显示）
  contextRight: "...",      // 可选，答对时替换 context
  contextWrong: "...",      // 可选，答错时替换 context
}
```

`context` 写中性版本（不说"对"或"错"）。有答对/答错差异时，用 `contextRight` / `contextWrong` 覆盖。三者都写时，`contextRight` 和 `contextWrong` 优先，`context` 作为兜底（例如从步骤条跳回重播时不重置答题状态）。

### `blackboardQ` vs `blackboard`：题前/题后分离

**原则**：如果答案在黑板上一眼可见，题目就失去意义。

| 字段 | 显示时机 | 内容 |
|---|---|---|
| `blackboardQ` | 学生答题前 | 只有题干需要的信息，**不含答案**（无比较箭头、无结果公式） |
| `blackboard` | 学生答题后 | 完整版，含答案（比较箭头、绝对值结果等） |

**何时需要分开写**：当 `blackboard` 里含有答案信息（`compArrow`、公式结果、`calculator.result`）时，必须同时提供 `blackboardQ`（去掉答案部分）。若黑板本身不含答案，只需写 `blackboard`，`blackboardQ` 可省略。

### 何时添加

**必须加**：教授在 context 中提到"在黑板上画/写了某物"——数轴、公式、表格——而这个东西是学生理解本条知识点的视觉锚点。

**不必加**：教授只是板书一个词或句子（已经在 context 叙事中说清楚了）；氛围性动作（整理粉笔、转身等）。

### 支持的类型

#### `numberline`（数轴）

```js
blackboard: {
  type: "numberline",
  range: [-5, 5],          // 数轴显示范围
  label: "数轴",            // 可选，左上角小标题
  note: "原点 = 零 · 规则：越靠右越大",  // 可选，底部注释

  // 可选：区域着色 + 标签（用于分类讲解）
  regionLabels: {
    left:   "负整数",   // 原点左侧染蓝
    right:  "正整数",   // 原点右侧染绿
    origin: "零"       // 原点正下方文字
  },

  // 可选：圆形标记点，style 取 "highlight"（金）/ "dim"（灰蓝）/ "accent"（绿）
  marks: [
    { value: -4, style: "dim" },
    { value: -1, style: "highlight" }
  ],

  // 可选：比较箭头（从 from 指向 to，金色）
  compArrow: { from: -4, to: -1, label: "更大" }
}
```

#### `formulas`（公式列表）

```js
blackboard: {
  type: "formulas",
  label: "绝对值",           // 可选，左上角小标题
  lines: [                  // 每行一条字符串，严格等宽对齐
    "| -5 | = 5",
    "|  5 | = 5",
    "|  0 | = 0"
  ],
  note: "到零的距离，结果永远非负"  // 可选，底部注释
}
```

#### `calculator`（计算器）

用于让学生亲自按键验证计算结果（如绝对值、开方）。这是一种**交互型黑板**，只放在 `blackboardQ`，不放在 `blackboard`。

`calculator` 支持三种写法：

1. **单键演示**：提供 `highlightKey`，学生按下高亮键后显示 `result`，随后进入解释。
2. **按键序列演示**：提供 `sequence`，不提供 `question`。学生必须依次按完序列中的键，屏幕显示 `result`，然后出现"继续"按钮；学生点击后进入解释。用于"让学生操作验证"，但不额外考问结果。
3. **按键序列 + 提问**：提供 `sequence` 和 `question`，学生必须依次按完序列中的键，屏幕显示 `result` 后再出现 `question` 选项；答对/答错会像普通课中提问一样显示反馈，再进入解释。

```js
blackboardQ: {
  type: "calculator",
  display: "-5",       // 屏幕初始显示值
  highlightKey: "|x|", // 高亮提示的按键（金色边框，提示学生按这里）
  result: "5"          // 按下高亮键后屏幕变成的值
}
// 答题后显示 blackboard（formulas 或其他类型），展示结论
```

```js
blackboardQ: {
  type: "calculator",
  display: "0",              // 屏幕初始显示值
  sequence: ["−", "5", "|x|"], // 必须依次按下的键
  result: "5"                // 序列完成后屏幕显示值
},
interactionContext: "芬威克把那台旧计算器递给你。「绝对值，是一个数到零的距离。距离没有方向，所以结果不会是负数。」他把计算器推近一点，「按 −5，再按绝对值键。让机器验证这句话。」"
// 按完序列后显示 result 和"继续"按钮；点击后显示 blackboard + context
```

```js
blackboardQ: {
  type: "calculator",
  display: "0",              // 屏幕初始显示值
  sequence: ["−", "5", "|x|"], // 必须依次按下的键
  result: "5"                // 序列完成后屏幕显示值
},
question: {
  leadIn: "芬威克把那台旧计算器递给你。「按 −5，找绝对值键。」",
  text: "「结果是多少？」",
  options: ["5", "−5", "0"],
  answer: 0
}
// 答题后显示 blackboard（formulas 或其他类型），展示结论
```

**注意**：`calculator` 只放在 `blackboardQ`，不放在 `blackboard`。`blackboard` 改用 `formulas` 展示对应公式结论。

### 关键约束

- `lines` 使用 **ASCII 连字符 `-`** 表示负号，**禁止使用 Unicode 减号 `−`（U+2212）或 `&minus;`**——后者在 Courier New 中不等宽，导致列对齐错位。
- `lines` 的对齐完全依赖手动空格 + `white-space: pre` 渲染。写之前先在等宽字体编辑器里对好列，再填入。
- `label` 和 `note` 均为纯文本，不解析 HTML。

## 对白与排版规范

课堂内容在 UI 中由 `_formatContext()` 自动处理，写作时只需遵守以下约定：

### 对白用 `「」`，不用 `""`

所有教授直接说出的话必须用中文引号 `「」` 包裹：

```
「大于零的整数，就是正整数。」
```

`"` ASCII 双引号**绝对禁用**——它会在 JS 字符串中引发转义问题，导致课程文件加载失败（`window.subject_xxx` 为 null，学生点"好好学习"会直接进随便学学事件）。

### 自动换行逻辑

`_formatContext()` 会在以下位置插入 `<br>`：

- 句末标点（`。！？`）后紧跟 `「` 对白开始时
- `」` 对白结束后紧跟非标点普通文字时

即：叙事→对白、对白→叙事之间自动分行，**作者无需手动插入换行**，只需保证 `「」` 使用一致。

### 视觉效果

| 文字类型        | 样式                      |
| ----------- | ----------------------- |
| 普通叙事（氛围/动作） | 斜体，灰色 `#8899aa`         |
| 教授对白 `「」`   | 正体，暖金色 `#d4bb88`，字重 500 |

## keyPoint 交互模式速查

每个 keyPoint 只对应一种交互模式，取决于字段组合：

| 模式 | 字段组合 | 效果 |
|---|---|---|
| **纯讲解**（无互动） | 只有 `blackboard` + `context` | 直接显示黑板和解释，学生点"继续" |
| **选择题** | `question` + 可选 `blackboard`/`blackboardQ` | 显示题干和选项，答对/答错触发不同反馈 |
| **计算器单键演示** | `blackboardQ`（calculator 类型，`highlightKey`），无 `question` | 显示计算器，学生按高亮键后展示结果，自动推进 |
| **计算器序列演示** | `blackboardQ`（calculator 类型，`sequence`）+ 可选 `interactionContext`，无 `question` | 学生依次按键，完成后显示结果和"继续"按钮；点击后进入解释 |
| **计算器序列提问** | `blackboardQ`（calculator 类型，`sequence`）+ `question` | 学生依次按键，完成后显示选择题，答对/答错触发反馈 |

设计原则：**每课至少一个选择题或计算器交互**，纯讲解不应超过两连续 keyPoint。
