## 起点假设

**玩家在进入第一课时，对该科目一无所知。**

这不是夸张。一年级第一课的受众是：从未接触过这门学科的十一岁巫师学生。写作时必须严格遵守：

- **禁止使用任何未经本课介绍的术语**——哪怕"显而易见"。第一课第一个 keyPoint 出现的术语，必须在该 keyPoint 里定义。
- **禁止假设学生已经知道任何工具或模型**——数轴、坐标系、元素周期表、食物链，都需要先介绍再使用。
- **引入顺序必须自洽**：后出现的概念可以依赖前面已讲的概念，但不能反过来。
- **年级越低，零起点假设越严格**：KS3 第 1 课按零基础写；高年级课程可以引用同科目前置课程已建立的概念，但仍不能跨科目假设。

## 世界观约束

- 游戏时间：**1991 年**，玩家是霍格沃茨一年级新生
- 视角：**研究麻瓜学术的巫师**——认为麻瓜知识有独立价值，态度是真正的学术好奇，不是猎奇或俯视
- 知识内容必须**准确**，学生读完真的能学到东西
- 年级阶段对应英国课程标准：KS3（1–3年级）/ GCSE（4–5年级）/ A-Level（6–7年级）

## 举例原则

**可以用：**

- 魔法世界通用设定（魔药、魁地奇、对角巷、霍格沃茨建筑、咒语机制、魔法生物）
- 模糊化主体："某位变形术学生"、"一次草药课实验"、"巫师社会中普遍的现象"
- 麻瓜知识与魔法的真实交叉点（化学↔魔药、物理↔飞行、生物↔神奇动物、拉丁语↔咒语词源）

**不能用：**

- 原著具体情节或点名引用主要角色的经历
- 上帝视角（破坏代入感）
- 1991 年 09 月 02 日后才发生的事件

## 输出格式

### 课程正文（lesson 文件内容）

```
【第 X 课：课程标题】

导入（1–2 句）
用魔法世界现象引出本节麻瓜概念，符合该教授的开场风格。

正文（2–4 段）
每段一个知识点，知识准确，可穿插 1 个巫师视角例子。
语气和措辞贴合教授人设。

本课要点
· 要点一
· 要点二
· 要点三（至多三条）

[联动提示：与 XX 魔法课相关——一句话，有自然联动时才写]
```

### 题库（questionBank 文件内容）

每课 6 道题：选择题 5 道 + 开放题 1 道，格式：

```js
{
  lesson: X,
  questions: [
    {
      type: 'choice',
      difficulty: 1|2|3,       // 1=基础 2=理解 3=应用
      text: '题目文字',
      options: ['A. ...', 'B. ...', 'C. ...', 'D. ...'],
      answer: 'A',             // 正确选项字母
      knowledgePoint: '对应知识点名称',
      analysis: '解析，说明为什么这个答案是对的'
    },
    // ...共 5 道选择题，难度分布：基础 2 道、理解 2 道、应用 1 道
    {
      type: 'open',
      text: '开放题题目文字',
      scoringPoints: ['评分点一', '评分点二'],   // 2–3 条，每条对应一个得分维度
      maxScore: 4                                // 通常 4 或 6，视评分点数量而定
    }
  ]
}
```

题目中的情境可以用魔法世界背景包装，但考查的是真实学科知识。
开放题考查对本课核心概念的理解或迁移应用，不考记忆，鼓励用自己的话解释或举例。

### 课程级别字段

每个 `lesson`（课程）对象除了标准的 `keyPoints` 外，应该包含：

```js
{
  atmosphere: "...",           // 开场氛围
  opening: "...",              // 老师的开场白，含今天学习目标的暗示
  keyPoints: [...]             // 知识点数组
  lessonSummary: "...",        // 课后总结：今天学了什么（60–100 字）
  nextLessonPreview: "...",    // 下一课预告：为什么要学下一个话题（30–60 字）
}
```

**设计原则**：

- `lessonSummary` 用第一人称复述，从学生的角度总结今天的收获。不是"我讲了"，而是"你们学了"。
- `nextLessonPreview` 制造对下一课的好奇或期待，通常是"现在你会 X，下一课我们要 Y"的逻辑链。
- 两者都是**故事化**的，不是生硬的列表。

**示例**：

```
lessonSummary: "今天学了三件事：第一，数轴是数字的地理位置——越靠右越大，这是唯一的规则。第二，整数分成三个家族——正整数、负整数、零，各自有各自的位置。第三，最容易出错的是负数比较——−1 比 −4 大，因为离零更近。还有，绝对值就是距离，永远不会是负数。"

nextLessonPreview: "下一课，我们从整数走到分数——同一条数轴，但这次要放下更小的东西。你们会发现，整数其实是分数的特殊情况。"
```

## keyPoint context 写作原则

每个 `keyPoint` 由两部分组成：`point`（知识点标题）和 `context`（课堂场景段落）。

### 定义必须明确写出

`context` 的核心职责是**让学生在做题前已经学过该题考查的定义**。

**不够的写法（只有场景，没有定义）：**

> 芬威克在黑板上画了一条数轴，指着中间的点说这个位置很特殊，让大家思考它和左右两侧的区别。

**正确的写法（场景中嵌入完整定义）：**

> 芬威克在黑板右侧写了两个字：正整数。「大于零的整数——」他在数轴右半段点了三下，「1、2、3，向右延伸，没有尽头。」……「零是整数，但它既不是正整数，也不是负整数。」

规则：**第一次引入某个术语的 keyPoint，必须在 context 里明确给出定义**（"X 是……的……"或"X——条件"）。定义可以包裹在教授的对白或板书动作里，但不能只靠暗示。

### 定义与叙事融合，不割裂

- 定义句紧跟术语首次出现，不推迟到段末
- 教授对白 `「」` 用来承载关键定义或强调，叙事文字描述动作/氛围
- 每个 keyPoint context 约 150–250 字；一段到底，不分段

***

## 小黑板（blackboard）规范

每个 `keyPoint` 可以附带一个可选的 `blackboard` 字段，在知识点标题与 context 文字之间渲染一块深绿色黑板区域。

### keyPoint 完整字段结构

```js
{
  point: "知识点标题",
  blackboard: { ... },      // 可选，答题后显示的黑板（含答案、箭头、结果）；也可写成 [{...}, {...}] 显示多块板书
  blackboardQ: { ... },     // 可选，答题前显示的黑板（不含答案——见下文）；也可写成数组
  question: { ... },        // 可选，课中提问；calculator 可配合 question 做按键后提问
  interactionContext: "...", // 可选，无 question 的互动说明；如计算器按键演示前的引导语
  context: "...",           // 答题后显示的解释（兜底，无 question 时也显示）
  contextRight: "...",      // 可选，答对时替换 context
  contextWrong: "...",      // 可选，答错时替换 context
}
```

`context` 写中性版本（不说"对"或"错"）。有答对/答错差异时，用 `contextRight` / `contextWrong` 覆盖。三者都写时，`contextRight` 和 `contextWrong` 优先，`context` 作为兜底（例如从步骤条跳回重播时不重置答题状态）。

### `blackboardQ` vs `blackboard`：题前/题后分离

**原则**：如果答案在黑板上一眼可见，题目就失去意义。

| 字段 | 显示时机 | 内容 |
|---|---|---|
| `blackboardQ` | 学生答题前 | 只有题干需要的信息，**不含答案**（无比较箭头、无结果公式） |
| `blackboard` | 学生答题后 | 完整版，含答案（比较箭头、绝对值结果等） |

**何时需要分开写**：当 `blackboard` 里含有答案信息（`compArrow`、公式结果、`calculator.result`）时，必须同时提供 `blackboardQ`（去掉答案部分）。若黑板本身不含答案，只需写 `blackboard`，`blackboardQ` 可省略。

**多块板书**：当同一个 keyPoint 需要同时展示公式和计算器，或同时展示定义板书与辅助图示时，`blackboard` / `blackboardQ` 可以写成数组，例如 `blackboardQ: [{ type: "formulas", ... }, { type: "calculator", ... }]`。数组顺序就是 UI 中从上到下的显示顺序。

### 何时添加

**必须加**：教授在 context 中提到"在黑板上画/写了某物"——数轴、公式、表格——而这个东西是学生理解本条知识点的视觉锚点。

**不必加**：教授只是板书一个词或句子（已经在 context 叙事中说清楚了）；氛围性动作（整理粉笔、转身等）。

### 黑板文案一致性硬规则

凡是课程文案里写到黑板上出现了具体内容，UI 黑板就必须出现对应内容。这里的"课程文案"包括 `atmosphere`、`opening`、`question.leadIn`、`context`、`contextRight`、`contextWrong`，不只限于 `context`。

必须补板书的触发词包括但不限于：

- "黑板上写了/写下/列出/标着/标注"
- "黑板上画了/画出/画成/圈出/划线"
- "在黑板上算/一步步写/演示"
- "指着黑板上的……"

处理原则：

- 如果文案说黑板上有公式、数字、标题、表格或步骤，`blackboardQ` / `blackboard` 的 `formulas.lines` 必须列出它。
- 如果文案说黑板上有数轴、比较箭头、标记点，优先用 `numberline`；题前用 `blackboardQ`，题后用 `blackboard` 补答案箭头或结论。
- 如果文案说黑板上有几何图形，但当前 UI 没有专用图形组件，必须先用 `formulas.lines` 写出可读的板书图示或结构说明，例如"图示：等边 / 等腰 / 不等边"、"圆心 O —— 半径 r —— 圆周"、坐标轴 ASCII 图。不能因为没有图形组件就让黑板为空。
- 如果 `atmosphere` 或 `opening` 已经描述了开场黑板内容，通常应并入第一个 keyPoint 的 `blackboardQ`，让学生进入讲课时能看到同一块黑板上的内容。
- 答题后文案如果写"芬威克在黑板上写/算/画……"，对应内容必须出现在题后的 `blackboard`；不能只藏在文字里。

### 计算器一致性硬规则

凡是课程文案里写到教授或学生实际使用计算器，UI 必须显示 `calculator`。这里的"使用"包括"按了/输入/显示/屏幕显示/让学生按/重复按/计算器算出"等。

处理原则：

- 如果计算器只是 `atmosphere` 里的道具（例如"计算器放在讲台正中"），但本 keyPoint 没有按键、输入或屏幕结果，可以不做交互。
- 如果文案写"按了几个键"或"显示某个结果"，至少要在 `blackboardQ` 中放一个 `calculator`，用 `display` 表示屏幕当前结果。
- 如果文案要求学生按键验证，必须用 `calculator` 的 `highlightKey` 或 `sequence`。
- 如果同一个 keyPoint 既需要公式板书又需要计算器，`blackboardQ` 写成数组：先放公式板书，再放计算器，或按课堂视觉顺序排列。

### 支持的类型

#### `numberline`（数轴）

```js
blackboard: {
  type: "numberline",
  range: [-5, 5],          // 数轴显示范围
  label: "数轴",            // 可选，左上角小标题
  note: "原点 = 零 · 规则：越靠右越大",  // 可选，底部注释

  // 可选：区域着色 + 标签（用于分类讲解）
  regionLabels: {
    left:   "负整数",   // 原点左侧染蓝
    right:  "正整数",   // 原点右侧染绿
    origin: "零"       // 原点正下方文字
  },

  // 可选：圆形标记点，style 取 "highlight"（金）/ "dim"（灰蓝）/ "accent"（绿）
  marks: [
    { value: -4, style: "dim" },
    { value: -1, style: "highlight" }
  ],

  // 可选：比较箭头（从 from 指向 to，金色）
  compArrow: { from: -4, to: -1, label: "更大" }
}
```

#### `formulas`（公式列表）

```js
blackboard: {
  type: "formulas",
  label: "绝对值",           // 可选，左上角小标题
  lines: [                  // 每行一条字符串，严格等宽对齐
    "| -5 | = 5",
    "|  5 | = 5",
    "|  0 | = 0"
  ],
  note: "到零的距离，结果永远非负"  // 可选，底部注释
}
```

#### `calculator`（计算器）

用于让学生亲自按键验证计算结果（如绝对值、开方）。这是一种**交互型黑板**，只放在 `blackboardQ`，不放在 `blackboard`。

`calculator` 支持三种写法：

1. **单键演示**：提供 `highlightKey`，学生按下高亮键后显示 `result`，随后进入解释。
2. **按键序列演示**：提供 `sequence`，不提供 `question`。学生必须依次按完序列中的键，屏幕显示 `result`，然后出现"继续"按钮；学生点击后进入解释。用于"让学生操作验证"，但不额外考问结果。
3. **按键序列 + 提问**：提供 `sequence` 和 `question`。UI 先显示 `question.leadIn` 与 `question.text`，选项先禁用；学生依次按完序列中的键，屏幕显示 `result` 后，选项变为可答。答对/答错会像普通课中提问一样显示反馈，再进入解释。

```js
blackboardQ: {
  type: "calculator",
  display: "-5",       // 屏幕初始显示值
  highlightKey: "|x|", // 高亮提示的按键（金色边框，提示学生按这里）
  result: "5"          // 按下高亮键后屏幕变成的值
}
// 答题后显示 blackboard（formulas 或其他类型），展示结论
```

```js
blackboardQ: {
  type: "calculator",
  display: "0",              // 屏幕初始显示值
  sequence: ["−", "5", "|x|"], // 必须依次按下的键
  result: "5"                // 序列完成后屏幕显示值
},
interactionContext: "芬威克把那台旧计算器递给你。「绝对值，是一个数到零的距离。距离没有方向，所以结果不会是负数。」他把计算器推近一点，「按 −5，再按绝对值键。让机器验证这句话。」"
// 按完序列后显示 result 和"继续"按钮；点击后显示 blackboard + context
```

```js
blackboardQ: {
  type: "calculator",
  display: "0",              // 屏幕初始显示值
  sequence: ["−", "5", "|x|"], // 必须依次按下的键
  result: "5"                // 序列完成后屏幕显示值
},
question: {
  leadIn: "他把计算器推到前面，「绝对值，」他停顿，「是一个数到零的距离。距离没有方向——往左走 5 步和往右走 5 步，你走的距离是一样的。」他看着全班，「按 −5，再按这个键。」他用粉笔指向计算器上的 |x| 键。",
  text: "「屏幕现在显示什么？」",
  options: ["5", "−5", "0"],
  answer: 0
}
// 显示顺序：黑板计算器 → question.leadIn → question.text（选项禁用）→ 学生按完 sequence → 选项可答 → 答题后显示 blackboard（formulas 或其他类型）+ 反馈
```

**注意**：`calculator` 只放在 `blackboardQ`，不放在 `blackboard`。`blackboard` 改用 `formulas` 展示对应公式结论。

#### `audio`（行内发音按钮，仅用于 `formulas` 类型）

用于语言类课程（如拉丁语）中为每行词汇配上可点击的发音按钮（🔊）。

```js
blackboard: {
  type: "formulas",
  label: "拉丁语元音",
  lines: [
    "a  =  [a:]  如 fAther",   // lineIndex 0
    "e  =  [e:]  如 thEY",     // lineIndex 1
    "i  =  [i:]  如 machIne",  // lineIndex 2
    "o  =  [o:]  如 bOAt",     // lineIndex 3
    "u  =  [u:]  如 rUde",     // lineIndex 4
    "",
    "每个元音只有一种发音"
  ],
  audio: [
    { text: "a", src: "audio/latin/lesson-1/vowel-a.wav" },   // lineIndex 省略 → 按数组下标 0
    { text: "e", src: "audio/latin/lesson-1/vowel-e.wav" },
    { text: "i", src: "audio/latin/lesson-1/vowel-i.wav" },
    { text: "o", src: "audio/latin/lesson-1/vowel-o.wav" },
    { text: "u", src: "audio/latin/lesson-1/vowel-u.wav" }
  ]
}
```

**`lineIndex` 字段**：指定该音频按钮出现在哪一行前面（0-indexed）。省略时按数组下标自动匹配。当音频行与数组下标不对应时（例如首行是标题、中间有空行），必须显式写 `lineIndex`：

```js
audio: [
  { text: "ca", src: "...", lineIndex: 1 },  // 第 0 行是标题，音频从第 1 行开始
  { text: "ce", src: "...", lineIndex: 2 },
]
```

**书写规则：**

- 有独立发音需要展示的内容，**必须拆成独立行**，不能合并在同一行——合并后只能放一个按钮，其他音频无处挂载。
- `audio` 应同时加在 `blackboardQ`（答题时）和 `blackboard`（答题后），让学生在选择答案前就能听到发音。
- 空行（`""`）不渲染按钮，即使 `lineIndex` 指向空行，按钮也不会出现。
- **列对齐注意**：有音频按钮的行会在文字前增加一个固定宽度按钮（约 28px），破坏纯 `white-space: pre` 的列对齐。因此**同一个黑板内**，若既有音频行又有非音频行，两者不宜强行对齐同一列——分组书写或在视觉上自然区分更合适。
- 中文字符按 **2 视觉单位**计算（英文字符 = 1 单位），用于手动对齐音节数等右对齐列。

**按钮交互行为：**

- 默认显示 🔊；点击后播放，显示 🔉；播放完毕自动回到 🔊。
- 播放中再次点击：立即停止并重置，回到 🔊，下次点击从头播放。

#### 拉丁语课程专项规范

**重音标注惯例（stress mark）**

板书中用**大写字母**标注重音音节，小写标注其余音节：

```
AM-i-cus   （重音在第一音节 AM）
pu-EL-la   （重音在第二音节 EL）
DO-mi-nus  （重音在第一音节 DO）
```

规则：
- 两音节词：重音永远在第一音节（倒数第二）→ 首音节大写
- 三音节+词：倒数第二音节为重音节（长音节）→ 该音节大写；否则倒数第三音节大写
- 单音节词（如 nox）：无需重音标注，不要误写成两音节

**TTS 发音输入校正表（用于 generate-latin-audio.py `text` 字段）**

espeak-ng `la` 模式不能直接用拉丁语正字法，需要将发音写法作为 `text` 输入：

| 拉丁正字 | TTS 输入 | 原因 |
|---|---|---|
| c（所有位置）| k | 古典拉丁 c 永远硬 [k]，espeak 默认会软化 |
| v | w | 古典拉丁 v = [w] |
| ae | aj | 古典拉丁 ae 双元音 |
| qu | kw | qu = [kw] |

示例：`"amicus"` → `text: "amikus"`，`"videt"` → `text: "widet"`

**音节计数**

计算音节数时以**元音数量**为准（每个元音 = 一个音节）：
- nox = 1个元音(o) = **1音节**（不可写成 NO-x 放入"2音节词"例子）
- lumos = 2个元音(u,o) = 2音节
- amicus = 3个元音(a,i,u) = 3音节

---

### 关键约束

- `lines` 使用 **ASCII 连字符 `-`** 表示负号，**禁止使用 Unicode 减号 `−`（U+2212）或 `&minus;`**——后者在 Courier New 中不等宽，导致列对齐错位。
- `lines` 的对齐完全依赖手动空格 + `white-space: pre` 渲染。写之前先在等宽字体编辑器里对好列，再填入。
- `label` 和 `note` 均为纯文本，不解析 HTML。

## 课堂 UI 分区规范

讲课阶段的视觉结构必须统一，所有 keyPoint 都按以下顺序呈现：

1. **标题区**：序号 + `point`
2. **黑板区**：`blackboardQ` 或 `blackboard`
3. **讲课区**：`context`、`interactionContext` 或 `question.leadIn`
4. **提问区**：`question.text` + `question.options`

### 分隔规则

- 黑板区、讲课区、提问区之间必须有横线分隔，不能挤在同一个视觉块里。
- 讲课区使用金色左边线样式，普通叙事为灰色斜体，教授对白为暖金色正体。
- 如果 `question` 带 `leadIn`，`leadIn` 属于讲课区，`question.text` 属于提问区；两者之间必须有横线。
- 如果没有提问，`context` 或 `interactionContext` 也必须使用同样的金边讲课区，不允许退回普通裸文本。

### 计算器序列提问的显示顺序

对于 `blackboardQ.type === "calculator"` 且同时有 `sequence` 和 `question` 的 keyPoint：

1. 先显示计算器黑板。
2. 在计算器下方显示 `question.leadIn`。
3. `question.text` 必须接在 `question.leadIn` 下方，中间有横线；选项先禁用。
4. 学生按完 `sequence` 后，屏幕显示 `result`，选项变为可答。
5. 答题后进入 `contextRight` / `contextWrong`，并显示题后 `blackboard`。

不要把 `question.text` 延后到按完计算器之后才出现；提问本身要先出现，计算器是用来得到答案的操作。

### 公式板书排版

`formulas.lines` 以黑板板书为准，必须整齐、紧凑：

- 每一行都是一条公式或说明，使用等宽字体渲染。
- 手动空格会被保留；写入前必须在等宽字体中检查列对齐。
- 空字符串 `""` 可用于分隔公式组，但只作为小间隔，不能制造大段空白。
- 绝对值、方程、表格类公式优先写成视觉上对齐的多行，不要把所有内容塞进一句 `note`。

## 对白与排版规范

课堂内容在 UI 中由 `_formatContext()` 自动处理，写作时只需遵守以下约定：

### 对白用 `「」`，不用 `""`

所有教授直接说出的话必须用中文引号 `「」` 包裹：

```
「大于零的整数，就是正整数。」
```

`"` ASCII 双引号**绝对禁用**——它会在 JS 字符串中引发转义问题，导致课程文件加载失败（`window.subject_xxx` 为 null，学生点"好好学习"会直接进随便学学事件）。

### 自动换行逻辑

`_formatContext()` 会在以下位置插入 `<br>`：

- 句末标点（`。！？`）后紧跟 `「` 对白开始时
- `」` 对白结束后紧跟非标点普通文字时

即：叙事→对白、对白→叙事之间自动分行，**作者无需手动插入换行**，只需保证 `「」` 使用一致。

### 视觉效果

| 文字类型        | 样式                      |
| ----------- | ----------------------- |
| 普通叙事（氛围/动作） | 斜体，灰色 `#8899aa`         |
| 教授对白 `「」`   | 正体，暖金色 `#d4bb88`，字重 500 |

## keyPoint 交互模式速查

每个 keyPoint 只对应一种交互模式，取决于字段组合：

| 模式 | 字段组合 | 效果 |
|---|---|---|
| **纯讲解**（无互动） | 只有 `blackboard` + `context` | 直接显示黑板和解释，学生点"继续" |
| **选择题** | `question` + 可选 `blackboard`/`blackboardQ` | 显示题干和选项，答对/答错触发不同反馈 |
| **计算器单键演示** | `blackboardQ`（calculator 类型，`highlightKey`），无 `question` | 显示计算器，学生按高亮键后展示结果，自动推进 |
| **计算器序列演示** | `blackboardQ`（calculator 类型，`sequence`）+ 可选 `interactionContext`，无 `question` | 学生依次按键，完成后显示结果和"继续"按钮；点击后进入解释 |
| **计算器序列提问** | `blackboardQ`（calculator 类型，`sequence`）+ `question` | 学生依次按键，完成后显示选择题，答对/答错触发反馈 |

设计原则：**每课至少一个选择题或计算器交互**，纯讲解不应超过两连续 keyPoint。

### 穆迪教授人设回顾

来自 `staff-data.js` 的关键信息：

| 要素 | 内容 |
|------|------|
| **背景** | 阿拉斯托·穆迪的侄女，在麻瓜世界生活7年，拆过两百多件麻瓜电器，做过仓库员工、电器维修学徒 |
| **性格** | 讲话快、手势多、像持续放电的麻瓜电器；课堂永远有演示、有噪音、有小爆炸 |
| **麻瓜情感** | 有过真正的麻瓜朋友，知道他们会为账单发愁、为球赛哭 |
| **catchphrase** | "我在麻瓜世界那七年……" |
| **quizStyle** | 热情、鼓励型、把失败当知识点 |
| **correct** | "漂亮！就是它！" |
| **wrong** | "炸了。不过炸也是数据。" |
| **教学特色** | 演示失败从不说"没关系"，而是说"这是今天的第二个知识点" |

### Quiz反馈写作原则

穆迪教授的反馈风格核心理念：**真实、耐心、把物理融入生活经验**。

#### 1. contextRight（答对反馈）

**原则**：简短肯定 + 核心点重申 + 麻瓜/魔法生活类比

**不好的写法**（太简单）：
```js
contextRight: "「正确。」穆迪教授点头，「这就是平均速度。」"
```

**好的写法**（符合人设）：
```js
contextRight: "对，就是平均速度。如果你想知道你飞过城堡塔楼时那一刻的速度，那才是瞬时速度。我以前在麻瓜工厂做质检的时候——他们测的就是整批零件的平均次品率，不会去量每一个——这和物理上的平均速度是一个道理。记住：平均看整体，瞬时看瞬间。"
```

**要点**：
- 开头简短肯定（"对"、"就是"），不用"正确"
- 重申核心概念
- 穿插麻瓜生活经验（工厂、公交、摩托车等）或魔法世界类比
- 用"记住"或"这是关键"收尾

#### 2. contextWrong（答错反馈）

**原则**：不打击 + 引导思考 + 耐心解释 + 麻瓜生活类比

**不好的写法**（太生硬）：
```js
contextWrong: "「不对。」穆迪教授纠正，「这是平均速度，不是瞬时速度。」"
```

**好的写法**（符合人设）：
```js
contextWrong: "嗯，不急。想想看，你从霍格沃茨到霍格莫德飞了10分钟——这10分钟里的速度是瞬时的还是平均的？对，是平均的。瞬时速度是某个特定时刻的速度，比如你经过打人柳时那1秒的速度。我以前在麻瓜那边修电视机的时候，师傅说要看'当前状态'，就是这个意思——瞬时。加速度是另一回事，我们等下会讲。"
```

**要点**：
- 开头用"嗯，不急"或"来，想一下"表示耐心
- 用问题引导学生自己思考
- 给出清晰的正确解释
- 穿插生活经验帮助理解
- 保持鼓励，不说"错"或"不对"

#### 3. question.leadIn（提问引导语）

**原则**：专业讲解 + 演示动作 + 麻瓜/魔法生活例子

**好的写法**：
```js
leadIn: "穆迪教授推了一下小车让它加速。「加速度描述的是速度变化的快慢。公式是 a = Δv/Δt。」她演示，「扫帚起飞的时候有加速度，高速飞行中改变方向也有加速度。麻瓜开车也是——踩油门加速，踩刹车减速，转弯的时候方向在变，加速度也存在。」"
```

**要点**：
- 先讲物理概念和公式
- 演示动作增强画面感
- 用魔法世界（扫帚）和麻瓜世界（汽车）双重类比

### 穆迪教授常用表达模式

#### 答对后的肯定语（随机使用）
- "对，就是这个。"
- "对，你抓住了关键。"
- "对，一样快。"
- "对，就是保持静止。"

#### 答错后的引导语（随机使用）
- "嗯，不急。"
- "来，想一下。"
- "嗯，这个容易搞混。"
- "嗯，再想想。"

#### 生活类比开头（随机使用）
- "我以前在麻瓜工厂做质检的时候……"
- "我在麻瓜那边修电视机的时候……"
- "我以前帮麻瓜师傅记数据的时候……"
- "你骑扫帚的时候想过这个问题吗……"
- "麻瓜开车也是——……"

#### 记忆点总结（答对/答错后都用）
- "记住：……"
- "这是关键：……"

### 禁止使用的表达

| 禁止 | 原因 |
|------|------|
| 「正确」/ 「错误」/ 「对」/ 「错」 | 太生硬，staff-data里"漂亮！就是它！"和"炸了。不过炸也是数据"是设计方向，不是字面照搬 |
| 直接说"不对"开头 | 打击学生积极性 |
| 机械套用固定句式 | 要自然融入生活经验 |

| 结尾 | 无 | "记住：……" |

## 地理教授·菲利克斯·韦斯莱 Quiz反馈风格规范

### 人设核心

菲利克斯是系里最年轻的教授，热情是真实的、孩子气的、会传染的。他对地理的崇拜没有表演成分，讲到某个地理事实会真的兴奋。他的弱点是备课不系统，容易跑偏——这种跑偏不是刻意搞笑，是他真的想起了什么就说出来了。

**重要**：他的热情有层次，不是每次都在喊叫。有时候是平静的惊叹，有时候是拍大腿，有时候是低声说"你们知道吗"。写的时候要让这个情绪自然变化，不要每条都是同等力度的感叹号。

---

### contextRight：答对了

**核心原则**：先认可，再延伸。延伸的方向是他自己感兴趣的地理细节，不是套话鼓励。

**延伸的几种自然方式**（不要每次都用同一种）：
- 补充一个相关的地理冷知识（"你们知道吗……"但不必每次都这么起头）
- 联系到课堂上的实物（指南针、地图、地球仪）——偶尔用，不要每条都提指南针
- 把知识点和魔法世界做一个真实的对照
- 感叹麻瓜研究这个现象的方式有多了不起

**节制原则**：指南针这个细节最多两三课出现一次。"你们知道吗"也是。重复道具会变成机械口头禅，破坏真实感。

**反面示例（太模板化）**：
```js
contextRight: "「对！X知识点！」他习惯性地从口袋里掏出指南针看了一眼，「你们知道吗？Z趣闻。」"
```
这个结构如果每条都长这样，三条之后学生就能预测下一条，真实感就消失了。

**正面示例**：
```js
// 平静的惊叹，不拿指南针，不喊叫
contextRight: "「对，就是这里。」他用手指在地图上绕了一圈，「有意思的是，麻瓜测出这条洋流的时间，比魔法部绘制对应魔力场分布图还早了将近一百年——纯靠温度计和绳子。」"

// 真的很兴奋，但是拍桌子不是喊叫
contextRight: "「完全正确！」菲利克斯拍了一下讲台，「我第一次看到这个数据的时候——书都掉地上了。整个撒哈拉沙漠六千年前是草原，你们能想象吗？」他摇了摇头，「气候就是这样，没人告诉你它会变。」"

// 低调的认可，侧重补充知识点
contextRight: "「不错。」他在地图上点了几个点，「沿海的城市通常比同纬度的内陆城市气温温和——这叫海洋性气候。伦敦的冬天比同纬度的莫斯科暖和很多，就是这个原因。」"
```

---

### contextWrong：答错了

**核心原则**：他不批评学生，他批评自己没讲清楚，或者批评这个知识点"太狡猾了"。语气是同一个战线的，不是评判者。

**他答错后的典型反应**：
- 挠红头发（这是真实的肢体动作，但也不必每条都出现）
- 先承认这道题确实容易弄混
- 用一个具体的地理场景重新解释，而不是重复原来的解释
- 有时候会岔开一句，说自己备课时也没想到这里会让人搞混

**反面示例（太生硬）**：
```js
contextWrong: "「不对。」菲利克斯纠正，「正确答案是X，原因是Y。」"
```

**反面示例（太固定公式）**：
```js
contextWrong: "「哎，想偏了！」他挠了挠红头发，「explanation」"
// 如果每条都是"哎，想偏了！他挠了挠红头发"，三条之后就是格式填空。
```

**正面示例**：
```js
// 他先承认这道题是个陷阱
contextWrong: "「嗯……这个位置我自己备课的时候也停了很久。」他走到地图旁边，「看，板块边界有三种——碰撞、张裂、平移。碰撞的地方不一定是山脉，有时候是海沟。太平洋那圈火环，其实大部分是板块俯冲，不是碰撞。我下次要在这里多讲一点。」"

// 他用场景重新解释，不只是说答案
contextWrong: "他挠了挠头，「来，我换个问法。」他拿起粉笔在黑板上画了一条河，「你看河流从上游到下游——上游落差大，流速快，主要做什么？侵蚀。下游流速慢，主要做什么？堆积。你选的那个答案，是上游的特征，但题目问的是下游。」他画了个箭头，「理解了吗？」"

// 他承认自己当年也弄错过
contextWrong: "「这个——」他停了一下，「我第一次看地形图的时候也把等高线的方向搞反了。等高线弯向低处，那里就是山脊；弯向高处，那里是山谷。刚好相反的。」他在黑板上画了两条线，「记住：弯向哪里，那里就是相反的地形。」"
```

---

### question.leadIn：提问引导

菲利克斯的引导不是"我来告诉你定义，然后考你"，而是他先被这个现象本身吸引，然后顺手把知识点带出来。

**好的 leadIn 结构**：
1. 用一个具体的场景或实物切入（地图、地球仪、某个真实地名）
2. 解释概念的时候像是在跟学生分享一个发现
3. 提问自然从场景里长出来，不是附加的考核

**示例**：

### 禁止的表达

| 禁止 | 原因 |
|------|------|
| 每条 contextRight 都以「对！」＋感叹号开头 | 力度一样就没有力度 |
| 每条都掏指南针 | 变成机械动作而不是人物细节 |
| 每条都"你们知道吗？" | 口头禅变成填空格式 |
| 答错直接说"不对/答案是X" | 不符合他的 quizStyle |
| contextWrong 里批评学生 | 他的风格是批评自己或者这道题 |
| 每条 contextWrong 都"哎，想偏了！他挠了挠红头发" | 三条之后就是模板 |

### 菲利克斯的语气层次（随情景变化）

| 情景 | 语气 | 示例起句 |
|------|------|--------|
| 知识点本身让他惊叹 | 真的兴奋，用动作体现 | 「拍了一下讲台」「在地图上用手比划」|
| 普通确认 | 平静肯定 + 补充细节 | 「对，就是这里。」「不错。」|
| 有趣的地理冷知识 | 低声说，像分享秘密 | 「你们知道吗……」（偶尔用）|
| 学生答错 | 同情式，觉得自己没讲好 | 「这个位置我备课时也停了很久。」|
| 跑偏到别的地理知识 | 自然的跑题 | 「哎，这让我想到……不过那是另一课的内容了」|
