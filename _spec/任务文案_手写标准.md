# 任务文案手写标准

本标准用于 `quest/quest-data.js` 及后续任务数据拆分文件。目标是把任务系统写成“活着的霍格沃茨公告板”，让玩家通过任务自然接触人物、地点、探索、魔药、决斗、商店、背包和好感系统，而不是每天按部就班完成上课清单。

任务可以是日常、支线、人物委托、地点传闻、教授跑腿、朋友组队、材料请求或轻调查。无论任务大小，都必须像霍格沃茨当天真的发生了一件小事。

## 核心目标

任务不是“完成行为换奖励”，而是给玩家一个进入校园生活的理由。

合格任务必须至少做到三件事：

- 让玩家知道是谁、在哪里、因为什么需要帮助。
- 让目标行为像任务情境的自然结果，而不是系统指令。
- 让奖励与人物、地点、难度或后果相配，不像固定模板。

优先写：

- 帮同学找东西：蟾蜍、棋子、课本、信件、围巾、跑掉的宠物、被魔法物件藏起来的小物。
- 给教授跑腿：送材料、补药剂、整理样本、查资料、把东西交到指定地点。
- 调查传闻：盔甲换姿势、画像吵架、楼梯改路、图书馆纸条、猫头鹰异常、某个走廊的怪声。
- 和朋友组队：陪练、4v4 临时补位、试战术、帮朋友确认咒语反应。
- 地点小事：猫头鹰棚送信、温室处理材料、图书馆查脚注、决斗场补医疗箱、公共休息室传闻发酵。

避免把日常任务写成：

- 去上课。
- 探索一次。
- 熬一锅药。
- 参与一场决斗。
- 今天完成 X / Y / Z。

这些只能作为底层条件，不能作为任务本身的叙事。

## 数量与日期底线

一年级每日任务池必须至少提供 800 条可抽取任务。原因：一年级按 37 周计算，共 259 天，每天 3 条任务，需要 777 条任务才能做到整学年基本不重样，还必须给节假日、周末和特殊日期留出可完成任务余量。

抽取标准：

- 每个学年优先不重复抽取每日任务。
- 同一天 3 条任务不能重复。
- 昨天出现过的任务今天优先不再出现。
- 当可用池不足时才允许回退复用，但一年级任务池正常情况下不得触发回退。

日期可用性标准：

- 含 `courseStudy` / `goodStudy` 的任务必须标记为 `requiresClass: true`，或由系统自动识别为上课任务。
- 周末、圣诞假期、复活节假期、暑假、开学日等无课日期不能抽到上课任务。
- 假期任务必须使用可完成条件，例如 `explore`、`brewPotion`、`duelPlay`、`duel4v4Play` 或非课程复合条件。
- 可以使用 `holidayOnly: true` 编写只在假期出现的任务。
- 可以使用 `weekendOnly: true` 编写只在普通周末出现的任务。
- 节假日任务要体现假期中的霍格沃茨：留校学生、猫头鹰棚、节日布置、空长桌、壁炉、温室保温、门厅雪水、安静走廊，而不是普通上课日换皮。

## 基本数据单位

每条任务建议包含以下字段：

- `id`：稳定唯一，不因改文案轻易改变，避免破坏存档。
- `title`：像公告板标题或人物请求，不写成系统命令。
- `desc`：任务起因。必须包含人物、地点或事件钩子。
- `source`：委托来源，可以是人物、纸条、公告、传闻、课程边角笔记。
- `location`：任务气质发生地，不能只写“任意地点”。
- `hook`：一小句有画面、有性格或有余味的补充。
- `completionText`：完成时的短结算，体现人物反应、地点变化或后续余味。
- `icon`：服务气质，不要只按系统分类机械选图标。
- `category`：用于经济奖励和筛选，可继续使用 `study` / `duel` / `explore` / `brew` / `mix` 等。
- `condition`：底层完成条件，允许复用现有计数器。
- `conditionLabels`：把底层条件翻译成任务语义，例如 `explore` 显示为“寻找莱福”。
- `rewards`：钱、好感、学院分、道具、材料可四选一或组合。

### 标准示例

```js
{
  id: "daily_neville_toad",
  title: "纳威的蟾蜍又不见了",
  desc: "纳威站在公共休息室门口，抱着一个空盒子小声问你有没有看见莱福。去城堡里找找，它通常不在合理的地方。",
  source: "纳威的求助",
  location: "城堡走廊",
  hook: "盒子里还留着一点湿泥，像一条非常不可靠的线索。",
  completionText: "你在一处拐角附近听见熟悉的“呱”。纳威接过盒子时整个人都亮了一下。",
  icon: "🐸",
  category: "explore",
  weight: 10,
  condition: { type: "explore", count: 1 },
  conditionLabels: { explore: "寻找莱福" },
  rewards: [
    { type: "affinity", key: "neville", delta: 4 },
    { type: "item", name: "巧克力蛙", count: 1 },
    { type: "money", sickles: 2 },
  ],
}
```

不合格写法：

```js
{
  title: "出去走走",
  desc: "探索任意区域。",
  conditionLabels: { explore: "探索区域" },
}
```

问题：没有人物、地点、起因、可读性，也不能让玩家觉得霍格沃茨正在发生事。

## 任务类型标准

### 同学找东西

重点是同学的性格和丢失物的具体性。

可写对象：

- 纳威：蟾蜍、草药课材料、被弄乱的笔记、紧张但真诚的求助。
- 罗恩：巫师棋子、坏掉的棋盘、零食、嘴硬但很快感激。
- 赫敏：书目、脚注、参考资料、课堂遗漏、事实必须被说清楚。
- 哈利：陪练、防守节奏、需要有人一起确认某个判断。
- 露娜：奇怪观察、别人不当真的线索、温柔但不解释过度。
- 金妮：信件、小物、想保持体面的私人请求。
- 德拉科：挑衅、面子、输赢、用轻蔑掩饰在意。
- 韦斯莱双胞胎：试用品、恶作剧、听起来安全但很可疑的请求。

不要写成所有同学都“请你帮忙，谢谢”。每个人的开口方式、尴尬方式、感谢方式都要不同。

### 教授跑腿

教授不是任务发布机器。任务应体现他们的职业习惯和性格。

- 麦格教授：准时、克制、标准清楚；表扬可以只是点头。
- 斯内普：纸条短、要求冷、评价少；“没批评”本身就是结果。
- 弗立维教授：鼓励、细致、重视咒语动作和课堂示范。
- 斯普劳特教授：温室、植物照料、务实温和。
- 平斯夫人：图书馆秩序、借阅规则、压低声音。
- 庞弗雷夫人：医疗补给、伤药、严厉但保护学生。
- 海格：动物、禁林边缘、过分乐观地说“没事”。

教授委托必须有“专业痕迹”：材料、样本、批注、药瓶、评分表、温室规则、借阅记录，而不是泛泛的“教授需要帮忙”。

### 传闻调查

传闻要轻、有趣、可疑，但不要每条都像主线谜案。

适合题材：

- 画像互相告状。
- 盔甲换姿势。
- 楼梯临时改道。
- 图书馆纸条和借阅记录。
- 猫头鹰送错信。
- 公共休息室流言越传越离谱。
- 费尔奇巡逻路线变化。
- 皮皮鬼留下的小麻烦。

调查结果必须有后果或余味：

- 传闻被澄清。
- 找到一件小物。
- 得到材料。
- 某个人对你多一点信任。
- 玩家知道某地点还有更多可探索之处。

避免：

- 每次都是“黑影、低语、纸条、脚印”。
- 每次都暗示大秘密。
- 结果只写“你什么也没发现”。

### 朋友组队决斗

决斗任务要有社交理由，不只是“打一场”。

可写方向：

- 罗恩试战术，但战术图可能画反。
- 哈利需要陪练防守节奏。
- 赫敏想验证课本里的咒语描述是否可靠。
- 双胞胎测试奇怪道具对反应的影响。
- 德拉科挑衅，需要用胜利来回应。
- 4v4 缺人临时补位，强调队友配合。

目标可以是 `duelPlay`、`duelWin`、`duel4v4Play`，但显示给玩家的 `conditionLabels` 必须写成任务语义，例如“陪哈利练习”“和朋友组队决斗”“赢下一场决斗回应挑衅”。

## 人物气质分离标准

任务中的人物必须可读出差异。不能把人物写成学院标签或功能按钮。

- 赫敏不是“学霸 NPC”，她在意事实、来源、步骤和严谨表达。
- 罗恩不是“搞笑 NPC”，他会嘴硬、尴尬、好意来得快，也会在输赢和朋友面前紧张。
- 哈利不是“主角 NPC”，他常常需要一个可靠同伴确认判断。
- 纳威不是“倒霉 NPC”，他的慌张里有真诚和努力。
- 德拉科不是“坏 NPC”，他在意位置、面子、输赢，防御性很强。
- 露娜不是“怪话 NPC”，她观察世界的方式不同，但不是随机胡言乱语。
- 金妮不是“害羞 NPC”，她有自己的主意，只是不总是解释给别人听。
- 教授不是奖励接口；他们的沉默、纸条、批改、动作和规则都必须像具体的人。

一条任务里只需要一点人物气质，不要把人物写成大段介绍。优先用动作、物件、说话节奏体现。

## 地点气质分离标准

任务必须让地点有功能、有气味、有规则。不能把地点名换掉后正文仍然成立。

- 图书馆：压低声音、借阅记录、书架秩序、平斯夫人、知识压力、书本脾气。
- 走廊：流动、画像、盔甲、楼梯、脚步、迟到、巡逻、偶遇。
- 魔药课教室：冷、湿、药水味、坩埚、标签、斯内普留下的短纸条。
- 决斗场：练习榜、评分表、医疗箱、队友站位、咒语反应。
- 温室：泥土、玻璃雾气、植物反应、照料规则、手套和花盆。
- 猫头鹰棚：羽毛、信件、风、鸟鸣、隐私和传信。
- 公共休息室：学院内部消息、棋盘、壁炉、作业、同学间的小尴尬。
- 大礼堂：传闻发酵、猫头鹰邮差、长桌、学院分、餐具和天气天花板。

同一批任务中，不要连续复用同一种地点母题。比如不能三条都写纸条，三条都写脚印，三条都写“走廊传来奇怪声音”。

## 目标与系统入口标准

任务应该引导玩家发现更多系统，而不是只奖励最短路径。

底层条件可以使用现有事件：

- `explore`：找东西、送信、调查传闻、跑腿、确认地点变化。
- `brewPotion`：补药剂、处理材料、完成教授要求、准备医疗箱。
- `duelPlay`：陪练、试战术、验证咒语、测试道具。
- `duelWin`：回应挑衅、争取练习榜、证明能力。
- `duel4v4Play`：朋友组队、临时补位、团队训练。
- `goodStudy`：查脚注、确认课上来源、听懂某个线索。
- `courseStudy`：只在有明确人物或地点理由时使用，不作为日常默认核心。
- `compound`：让一个小故事跨两个系统，例如“探索找材料 + 熬制药剂”“认真听课 + 现场验证”“补药剂 + 决斗场测试”。

显示目标必须用 `conditionLabels` 写成玩家正在做的事，而不是内部计数名。

合格：

```js
condition: { type: "explore", count: 1 },
conditionLabels: { explore: "寻找莱福" },
```

不合格：

```js
conditionLabels: { explore: "探索区域" },
```

除非任务本身就是“探索区域”的教学任务，否则不要用系统行为名当目标文案。

## 奖励标准

奖励可以是以下四类单独使用或组合：

- 钱：`money`，适合跑腿、补给、试用品、值日、帮忙采购。
- 好感：`affinity`，适合同学求助、教授委托、朋友陪练。
- 学院分：`housePoint`，适合教授认可、公共贡献、课堂相关、遵守规则。
- 道具/材料：`item` / `material`，适合找东西、探索、魔药、双胞胎试用品、地点发现。

奖励组合要符合任务来源：

- 纳威找蟾蜍：纳威好感 + 小点心/少量钱。
- 教授材料：学院分 + 少量钱或材料。
- 斯内普备用药剂：少量好感或学院分 + 钱，不要过度热情。
- 双胞胎试用品：道具 + 钱 + 双胞胎好感。
- 传闻调查：材料/钱/学院分，不一定给好感。
- 朋友组队：朋友好感 + 决斗相关材料/学院分/钱。

避免奖励完全机械同质化：

- 每条都是材料 + 学院分 + 2 西可。
- 所有人都给同样好感。
- 教授任务奖励像朋友送礼。
- 轻松任务给过高学院分或大量钱。

## 可读密度标准

每条任务应读起来像一个完整的小停留。

最低要求：

- `title` 不是功能词，能看出事件。
- `desc` 至少包含一个具体人物、物件、地点或传闻。
- `hook` 提供额外画面、幽默、性格或疑点，不重复 `desc`。
- `completionText` 有完成后的反应或变化，不只写“任务完成”。
- `conditionLabels` 是任务语义，不是系统语义。
- 奖励能反推任务来源。

文案长度建议：

- `title`：6-14 个汉字左右，短而有钩子。
- `desc`：35-70 个汉字左右，讲清起因和行动理由。
- `hook`：15-45 个汉字左右，补一个人物/地点细节。
- `completionText`：25-70 个汉字左右，给一点反馈和余味。

短不是问题，空才是问题。不要为了凑字数灌水；要补在动作、物件、地点机制、人物反应上。

## 原著气质与同人边界

本项目是粉丝创作，任务应尊重原著气质，但不要复述原著剧情或提前剧透后续年级。

必须：

- 一年级任务以新生视角、校园生活、轻魔法日常为主。
- 重要原著人物要符合气质，不写反常人设。
- 学院差异要有，但不能刻板化。
- 魔法物件、画像、幽灵、楼梯、猫头鹰、教授规则要自然融入生活。
- 不把每条任务都写成主线危机。

避免：

- 把霍格沃茨写成普通 RPG 委托板。
- 把所有斯莱特林写成坏人，所有格兰芬多写成热血莽撞。
- 让教授用现代游戏 NPC 语气发布任务。
- 让学生说过于网络化、现代化、出戏的句子。
- 复制原著长句或经典桥段；应写原创小事件。

## 批量扩写结构建议

扩充一批日常任务时，不要平均生产“课程、探索、魔药、决斗”四类模板。建议按“校园生活入口”分配：

- 25% 同学求助：找东西、送信、借书、陪练、解释误会。
- 20% 教授跑腿：材料、样本、药剂、借阅、课堂准备。
- 20% 地点传闻：走廊、图书馆、大礼堂、猫头鹰棚、温室、决斗场。
- 20% 朋友组队：决斗、4v4、咒语练习、战术测试。
- 15% 跨系统小冒险：探索 + 魔药、听课 + 调查、魔药 + 决斗、送信 + 发现传闻。

每 20 条任务至少覆盖：

- 8 个不同人物或来源。
- 6 个不同地点。
- 4 种奖励组合。
- 4 种底层条件。
- 至少 5 条非课程任务。
- 至少 5 条带人物好感奖励。
- 至少 5 条只靠地点气质成立，而不是靠名人露脸。

## 禁用模板

以下句式如果连续出现，应判定为同质化：

- “有人说……去看看。”
- “教授需要……帮他/她完成。”
- “今天完成……”
- “你发现事情并不简单。”
- “对方很高兴，感谢了你。”
- “胜负不重要，参与即可。”
- “这会让你更了解霍格沃茨。”

这些意思可以写，但必须落到具体人物、物件、地点和反应上。

## 审校清单

- [ ] 任务不是裸系统目标。
- [ ] `title` 有事件感，不是功能按钮。
- [ ] `desc` 有人物、地点、物件或传闻钩子。
- [ ] `source` 与 `location` 具体，不互相敷衍。
- [ ] `hook` 不重复 `desc`，有额外画面或性格。
- [ ] `completionText` 有人物反应、地点变化或余味。
- [ ] 人物气质与原著/项目设定一致。
- [ ] 地点气质可读，换地点名后不应仍然成立。
- [ ] `conditionLabels` 是任务语义，不是内部事件名。
- [ ] 奖励组合符合任务来源和难度。
- [ ] 同一批任务中人物、地点、奖励、目标不单调。
- [ ] 没有刻板学院描写。
- [ ] 没有现代网感和出戏表达。
- [ ] 没有过早剧透后续年级主线。
- [ ] 能让玩家觉得霍格沃茨今天自己在运转。
- [ ] 通过 `node tools/check-js-syntax.js`。
