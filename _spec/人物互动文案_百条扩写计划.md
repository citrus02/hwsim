# 人物互动文案：百条扩写计划

目标不是把 100 条写成 100 个换皮按钮，而是让玩家长期只找一个 NPC，也能读到足够多的关系层次。

## 数量目标

每个可结交角色最终应达到：

- `activeChat.events >= 100`：玩家主动找 NPC 聊天。
- `encounters >= 100`：人物线索、地点偶遇、行动后遇见、后续跟进。
- `proactive >= 20`：NPC 主动来找玩家。

`activeChat.events + encounters >= 200` 只是最低容量线，不代表质量达标。

## 分层写法

每个角色的 100+ 主动聊天应由这些池组成：

- `common`：跨年级日常池，负责基础生活感。
- `year1` 到 `year7`：年级专属池，负责原著年份气氛、成长和关系变化。
- `tier`：按好感阶段解锁的更深内容。
- `memory`：响应玩家经历、课程表现、决斗、探索、上次选择。

人物线索/偶遇 100+ 也必须分层：

- 地点偶遇：角色在真实地点做真实事情。
- 行动后遇见：上课、探索、决斗后自然撞见。
- 世界动态后续：传闻、课堂、关系波动引出的跟进。
- 玩家选择后果：上次帮忙、回避、误解、冒犯之后的延续。

## 主动来访标准

NPC 主动来找玩家必须“有原因”，不能只是随机弹窗。

合格原因包括：

- 好感阶段到了，角色愿意主动靠近。
- 玩家做过某件事，被角色看见或听说。
- 上次互动留下了记忆标签。
- 当前年级大事件让角色不得不找人说话。
- 角色自己的生活压力外溢到玩家这里。

主动来访每条至少要有：

- `opening`：一段完整场景，不少于地点线索 intro 的密度。
- `choices`：至少 2 个选择，一个接近，一个保持分寸或转向实际帮助。
- `response`：关系余味和后续记忆，不只加好感。
- `require`：至少包含 `minTier`、`cooldownDays`，必要时包含 `minGrade/maxGrade/grades` 和 `memoryTag`。

## 验收工具

运行：

```bash
node tools/audit-affinity-content.mjs
```

它会输出每个角色距离 `主动聊聊 100`、`人物线索 100`、`主动来访 20` 还差多少，以及 1-7 年级过滤后的最低可用内容。
